## Loon 语法依据

- [域名规则](https://nsloon.app/docs/Rule/domain_rule/)：`DOMAIN` 精确域名，
  `DOMAIN-SUFFIX` 标签边界后缀，`DOMAIN-KEYWORD` 域名包含关键词。
- [IP 规则](https://nsloon.app/docs/Rule/ip_rule/)：IPv4 使用 `IP-CIDR`，
  IPv6 使用 `IP-CIDR6`；`no-resolve` 不为域名主动查询 DNS 来匹配 IP。
- [订阅规则](https://nsloon.app/docs/Rule/sub_rule/)：订阅文件各行需使用 Loon
  支持的规则语法；策略由客户端的订阅设置指定。

保留本仓库的 IPv6 `IP-CIDR6` 写法。客户端只接收上述基础类型；
`AND`、`OR`、`NOT`、脚本、嵌套订阅及行内策略均不通过生成与发布校验。
未进行闭源 iOS 客户端运行测试；这里验证的是文档支持的语法与转换语义边界。

## Claude 域名与 IP

域名原始入口为 v2fly 的 `data/anthropic`。8 条后缀和 1 条精确专用 CDN 域名；
`servd-anthropic-website.b-cdn.net` 保持 `DOMAIN`，不扩大到整个共享 CDN。

IP 与 OpenAI 复用同一次下载的 `ASN.mmdb`，只选择 AS399358。
数据库组织名为 `Anthropic, PBC`，当前输出：

```text
IP-CIDR,160.79.104.0/23
IP-CIDR6,2607:6bc0:11::/48
IP-CIDR6,2607:6bc0::/48
```

[Anthropic 官方文档](https://platform.claude.com/docs/en/api/ip-addresses)
列出的入站 IPv4 和 IPv6 前缀与其中两条相符；额外 `2607:6bc0:11::/48`
来自本次 ASN 数据库。官方出站 `160.79.104.0/21` 是工具调用的源地址范围，
不能直接作为访问 Claude 的目标网段加入。没有加入共享云厂商的整个 ASN。
所选 ASN 全部缺失时终止构建，不复用旧网段，也不以其他组织的网段填补。

新增 `Claude.list`、`Claude-NoResolve.list`，以及域名、IP、IP-NoResolve 三份来源子集。
普通和 NoResolve 版本的匹配条件完全一致，仅 IP 条目的 DNS 行为不同。

## 转换及发布修复

1. v2fly 普通域名、精确域名或关键词损坏时终止构建。原先捕获全部
   `Unsupported` 后跳过，可能发布悄悄缩小的来源文件。不支持的正则仍完整记录后跳过。
2. AdGuard 正则含 `##` 等字符时，按正则解析，不先当作 cosmetic 条目丢弃。
   例如同时包含真实域名分支和 `##` 分支的例外不能被忽略；无法安全表达则终止构建。
   已有有限正则对字母转义和可选 `#` 的处理也补了回归验证。
3. 独立发布审计覆盖完整文件清单、基础类型和字段、UTF-8/LF、规范 CIDR、
   重复／空行／排序、聚合与来源一致、全部普通／NoResolve 对、实际条数、
   输出及审核文件哈希、输入清单和同一分支的提交一致性。暂存目录通过后才替换发布目录；
   PR 检查复用同一审计。
4. 报告新增 MMDB 构建版本、实际 ASN 组织名及地址族数量、Voice 数据时间、
   AdGuard 总清单元数据。隐私检查避免把通用执行账户名称误判为公开域名中的个人身份。
5. 每日两个 schedule 保留 05:17、06:43，明确设置 `Asia/Taipei`；失败时也尝试上传报告。
   [GitHub 官方 schedule 文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)
   已支持 IANA 时区。测试、生成、离线复现和审计全部通过后才提交规则及报告。
